# sdd-apply

Финализирует фичу: RFC уходит в архив, итоговая сводка — в `docs/specs/`.

## Когда использовать

- Реализация по RFC завершена, критерии приёмки закрыты
- Пользователь говорит «завершаем», «фича готова», «закрой спеку», «перенеси в архив»

## Workflow

### Шаг 1. Найти RFC

- Если пользователь указал фичу — открыть `docs/rfc/<slug>.md`
- Если не указал — показать RFC со статусом `implementing` и спросить, какую завершаем

### Шаг 2. Проверить готовность к закрытию

- Пройтись по чеклисту «Критерии приемки» — все пункты должны быть отмечены
- Если что-то не закрыто — показать список и спросить: доделываем (назад к **sdd-implement**) или закрываем с оговорками (незакрытое уйдёт в сводку как известные ограничения)

### Шаг 3. Перенести RFC в архив

- Обновить frontmatter RFC: `status: done`, добавить `completed: YYYY-MM-DD`
- Переместить файл: `docs/rfc/<slug>.md` → `docs/rfc/archive/<slug>.md`
- В git-репозитории использовать `git mv`

### Шаг 4. Создать сводку в docs/specs/

Создать `docs/specs/<slug>.md` (папку создать, если нет) по формату:

```markdown
---
title: "<название фичи>"
status: done
completed: YYYY-MM-DD
rfc: ../rfc/archive/<slug>.md
---

# Spec: <название фичи>

## Что сделано

<краткая сводка: итоговое состояние, что реально работает>

## Ключевые решения

<решения, принятые в ходе реализации, включая отклонения от RFC>

## Отклонения от RFC

<что сделали иначе и почему; если не было — «не было»>

## Известные ограничения / дальнейшие шаги

<незакрытые критерии, техдолг, идеи на будущее; если нет — «нет»>
```

Сводка — это снимок итогового состояния для тех, кто будет разбираться с фичей потом. Пишется по факту, а не по плану.

### Шаг 5. Отчитаться

Показать пользователю:

- RFC в архиве: `docs/rfc/archive/<slug>.md`
- Сводка: `docs/specs/<slug>.md`
- Предложить внести правки в сводку
