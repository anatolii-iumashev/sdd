# sdd-implement

Запускает реализацию фичи по готовому RFC.

## Когда использовать

- RFC создан и прошёл ревью (статус `review`/`approved`)
- Пользователь говорит «берём в работу», «начинаем делать», «реализуем по RFC»

## Workflow

### Шаг 1. Найти RFC

- Если пользователь указал фичу — открыть `docs/rfc/<slug>.md`
- Если не указал — показать список активных RFC из `docs/rfc/` (без `archive/`) и спросить, какой берём в работу

### Шаг 2. Проверить готовность RFC

Прочитать RFC и проверить:

- Статус не `draft` (если `draft` — предупредить и спросить, точно ли начинаем без ревью)
- Заполнены критерии приёмки и дорожная карта

Если критерии приёмки пустые или размытые — предложить сначала дополнить RFC (вернуться к **sdd-rfc**).

### Шаг 3. Составить план реализации

На основе разделов «Составляющие и особенности» и «Дорожная карта» RFC:

- Разбить работу на конкретные задачи
- Зафиксировать порядок и зависимости
- Создать todo-лист сессии (todowrite)

План показать пользователю перед стартом.

### Шаг 4. Обновить статус и начать работу

- Перевести статус RFC во frontmatter в `implementing`
- Реализовывать задачи по плану
- По ходу работы отмечать выполненные пункты в чеклисте «Критерии приемки» прямо в файле RFC (`- [ ]` → `- [x]`)

### Шаг 5. Проверка по критериям

Когда все задачи выполнены — сверить результат с каждым критерием приёмки:

- Все критерии закрыты → предложить завершить фичу через **sdd-apply**
- Что-то не закрыто → зафиксировать в RFC, что осталось, и обсудить с пользователем

## Правила

- Не выходить за рамки RFC: если в работе всплывает что-то за пределами спеки — зафиксировать в разделе «Открытые вопросы» RFC и спросить пользователя
- Существенное отклонение от решения, описанного в RFC → сначала обновить RFC, потом код
